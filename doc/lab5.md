### Отчет по лабораторной работе №5: «Технический долг»
**Проект:** QueueBot (Spring + React + TG Bot)

#### 1. Инспекция проекта на наличие технического долга

| Признак техдолга | Текущее состояние в QueueBot |
| :--- | :--- |
| **Непонятный / нечитабельный код** | В коде бота и контроллерах Spring присутствуют «магические строки» (например, пути эндпоинтов или тексты сообщений). Отсутствует Javadoc для бизнес-логики очередей. |
| **Дублирующийся код** | Логика валидации данных (например, формат `telegram_tag`) дублируется на фронтенде (JS) и на бэкенде (Java). Модели данных студентов описываются дважды (DTO и Entity) без использования мапперов (MapStruct). |
| **Отсутствие автоматизации** | **Критично:** Согласно бэклогу (WTF-19), линтинг и CI еще не настроены. Отсутствуют Unit-тесты для сервисов регистрации и алгоритмов смены мест в очереди. |
| **Запутанная архитектура** | Прямая связь между Бэкендом и ТГ-ботом через HTTP Secret. При падении одного из сервисов нет механизма очередей сообщений (RabbitMQ/Kafka) или повторных попыток (Retry), что делает систему хрупкой. |
| **Медленные средства** | Сборка Docker-контейнеров каждый раз происходит «с нуля» без использования кэширования слоев для зависимостей Maven/NPM. |
| **Документация** | Отсутствует Swagger/OpenAPI. Фронтенд-разработчик вынужден смотреть исходники Java, чтобы понять структуру JSON-ответов. |
| **Тестовая среда** | Нет staging-сервера. Все тестирование происходит локально на `localhost`. |
| **Циклы интеграции** | Ручное развертывание. Интеграция считается завершенной только после ручного «прокликивания» всех кнопок в ТГ и Браузере. |

#### 3. Сравнение объема долга и недоимплементированных фич

*   **Объем техдолга (TD):** 21 Story Points.
*   **Объем новых фич из Backlog (WTF-17 + доработки):** ~9 Story Points (согласно скриншоту).
*   **Соотношение:** Технический долг в **2.3 раза превышает** объем оставшихся задач текущего бэклога. Это тревожный сигнал («Красная зона»), означающий, что проект может «задохнуться» при добавлении более сложных функций (например, логики бригад).

---

#### 4. Выводы и корректировка плана разработки

**Обоснование необходимости устранения:**
На текущий момент проект функционален (Спринт 2 завершен), но полное отсутствие автотестов и CI/CD (задача WTF-19 в бэклоге) делает невозможным масштабирование. Любое изменение в логике «Смены мест» (WTF-17) может незаметно сломать авторизацию.

**Корректировки плана:**
1.  **Заморозка новых фич:** Не приступать к задаче WTF-17 («Команда /status»), пока не будет выполнена задача WTF-19 (CI/CD) и TD-1 (Swagger).
2.  **Правило Boy Scout:** При реализации новых команд в ТГ-боте обязательно выносить текстовые строки в конфиги (TD-4).
3.  **Definition of Done (DoD):** Обновить критерии приемки задач для следующего спринта:
    *   Код прошел проверку линтером в GitHub Actions.
    *   Новый метод контроллера покрыт хотя бы одним Happy Path тестом.
    *   API-эндпоинт отображается в Swagger.

**Изменение плана (Sprint 3):**
*   *Вместо:* «Реализация всех команд ТГ-бота».
*   *Станет:* «Настройка CI/CD (WTF-19) + Документирование API (TD-1) + Команда /status (WTF-17)». 
*Выделяем 50% мощностей команды на закрытие техдолга, иначе стоимость разработки новых фич вырастет экспоненциально.*
